Design Philosophy:
- Minimal but expressive (never bland, never overdesigned)
- Hierarchy starts with empty space: Owen values negative space almost above everything else. It communicates without saying anything — restraint, professionalism, and the sense that every detail was considered. Prefer generous void over filling the canvas.
- Strong typography hierarchy (after space: type, numbers, corners — see below)
- Intentional spacing system and alignment
- Subtle, satisfying animations
- Interfaces should feel alive, not distracting
- Owen prefers typography that feels a bit brutal and abstract — editorial tension, not generic SaaS.
- Main titles: very large, bold, and dominant.
- Hierarchy via numbers (01, 02, …): treat as a first-class visual system — they may read large with semi-blur, or small and sharp; use for structure and rhythm.
- Sometimes use one uniform face in all caps for a section or label system (disciplined, not random).
- Page corners: each viewport should feel considered — subtle marks, labels, frames, or meta text in the corners (tasteful, not noisy).

Avoid:
- Generic startup UI
- Overused patterns with no personality
- Excessive gradients/flashy effects
- Cluttered layouts

Target Visual Quality:
- Apple-level clarity
- Pinterest-level inspiration
- Slight edge from fashion/art influence

UI Style Guidelines:
- Colors & materials (canonical — do not default to warm or saturated accents):
  - Core palette: clean **white** (#fff) for the main page field, **true black**, and **grey** for secondary surfaces and hairlines. Use **greyish off-white** only for tinted bands or cards (`--section-tint`), not as the global page fill unless a specific section calls for it. No orange; avoid purple or rainbow accents unless Owen asks.
  - **Blur** is part of the visual system (frosted nav, scroll-reveal blur resolving to sharp type, backdrop-filter) — treat it like a tonal layer, not decoration spam.
  - Contrast hierarchy: black text on off-white for primary reading; muted greys for secondary; hairline borders with low-alpha black/grey.
  - **Black on black** (optional, never required): Owen likes it when one plane reads **matte** (soft, flat, absorbs light) and another reads **slick / shiny** (tight highlight gradient, specular edge, or glass). This is **hard to read** — only use for **large** elements (hero-scale type, big numerals, section shells) where legibility stays effortless. Do not use black-on-black for body copy or small UI.
  - **Shine on black**: subtle highlights (diagonal gloss, thin light rim) can sit on large dark surfaces; keep it restrained and test contrast.
  - If a reference site (e.g. example portfolios) uses bold color fills, **do not import those hues** — borrow motion and composition only; keep Owen’s neutrals.
- Typography:
  - Clean sans-serif (SF Pro / Inter / Helvetica Neue feel) as a base; layer in brutal/abstract hierarchy (big bold titles, numeric index system, optional all-caps bands).
  - Clear hierarchy (large hero text, smaller support text) — outside the home hero, lean into scroll-reveal type motion (see Interaction).
  - Breathing room and readable line spacing
- Spacing (non-negotiable):
  - Empty space is a primary design voice, not leftover area — use it to structure attention and signal confidence.
  - Generous padding and margins; resist crowding; let sections breathe.
  - Consistent vertical rhythm
  - No cramped sections
- Components:
  - Rounded corners generally 8px-16px
  - Soft shadows
  - Clean card systems where useful

Interaction + Motion Requirements:
- Motion quality is high priority.
- Scroll is a primary canvas: prefer rich, layered motion — multiple animated properties (opacity, blur, translate, scale, stagger) tied to scroll position or intersection, not a single fade everywhere.
- First-time reveal: much of the text should slide up slightly, ease in opacity, and use a touch of blur that resolves as it settles (blur + fade + slide — tuned so it stays readable and performant).
- Include many interactive elements: hovers, toggles, draggable or playful details where appropriate; surprise and delight without breaking usability.
- Use:
  - Subtle hover states
  - Smooth transitions (200ms-400ms baseline)
  - Small scale/opacity shifts
  - Staggered children and scroll-driven choreography where it reinforces hierarchy
- Avoid:
  - Heavy gimmicks
  - Distracting animations
  - Motion that hurts readability or accessibility (respect prefers-reduced-motion)
- Desired feel:
  - Responsive
  - Intentional
  - Slightly premium
  - Interesting UI/UX — memorable patterns, clear feedback, product-real behaviors
- Navigation behavior requirement:
  - Sticky/floating rectangular nav surface with smooth corners and blur background.
  - Nav should sit slightly lower from top to reveal its shape.
  - On scroll, nav should dynamically condense (notably reduced width) with smooth transition.

Mobile-First Requirement (Vital):

- No layout breakage, clipping, or cramped spacing at smaller sizes.
